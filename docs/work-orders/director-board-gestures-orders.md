# 확인 칸 닫기 · 챕터 콤보 따라가기 · [대본] 판 우클릭 · Delete · 빈 선택지 상자 (Q0–Q7) — 2026-11-18

- 「치명적인 에러가 있는데, 챕터 지우기, 장면지우기를 했을 때, 확인창을 끌 방법이 없습니다. 다른 공간을 클릭하면 자동으로 꺼지도록 해주십시오.」(Q1)

> **상태: 진행 중.**

## 1. 지금

- 확인 칸(`ConfirmFlyout`)은 Avalonia 플라이아웃의 바깥 누름 닫기에만 기댄다. 헤드리스에서는 바깥을 누르면 닫히지만(툴바 단추에 붙었을 때 · 붙은
  자리가 나무에서 떨어졌을 때 모두), 소유자의 화면(데스크톱 · 하이어아키 차림표에서 띄운 확인 칸 — P3 전의 길)에서는 닫히지 않았다. 차림표가 닫히며
  같은 창의 바깥 누름 받이(light dismiss 층)를 감추는 것으로 본다(재현은 헤드리스에서 되지 않는다). 확인 칸을 닫는 손잡이가 플라이아웃 하나뿐이다.
  닫혀도 셸의 시험 손잡이(`RemoveConfirmButton` · `DeleteConfirmButton`)는 확인을 눌렀을 때만 비워진다.
- [대본] 챕터 콤보는 활성 판(`ActiveFileId`)을 비추는데, 다시 그릴 때(`Rebuild`)와 챕터 목록이 올 때만 맞춘다 — 하이어아키 · 판의 빈 곳에서 다른 챕터를
  골라 활성 판이 바뀌어도 콤보는 그대로다. 판에서 다른 챕터의 카드를 누르면 활성 판도 바뀌지 않는다.
- [구성] 챕터 콤보는 항목이 ChapterId이고 보이는 글도 ID다([대본] 콤보는 항목은 ID, 보이는 글은 이름).
- [구성] 툴바 [전체 보기](`FitChapterButton`).
- [대본] 판의 빈 곳 우클릭은 아무 일도 없다(좌클릭은 범위 선택 · 누르기만 하면 그 자리의 장면 · 챕터 · 프로젝트를 고른다).
- Delete 키는 아무 일도 없다.
- [대본] 판 선택지 칸 — 이은 칸 · 적은 칸 · 자동 칸은 점 옆에 글이 서지만, 빈 칸은 「＋ 선택지」 글이 **보이지 않는다**: 글자색을 `null`로 못박아
  (`Foreground = live ? dot : null`) 칠할 붓이 없다. 점만 보여 적을 수 있는 자리인지 모른다.

| Q7 | **빈 선택지 칸에 「빈 선택지」 상자** — [대본] 판의 빈 칸(자동 칸이 아니고 문구가 없는 칸) 점 옆에 네모 칸을 두고 회색 「빈 선택지」를 적는다. 누르면 그 자리에서 문구 칸이 열린다(지금과 같다 — 칸의 폭도 같게 해 누를 때 들썩이지 않는다). 보이지 않던 「＋ 선택지」는 걷는다. 시험 · 눈으로 |
