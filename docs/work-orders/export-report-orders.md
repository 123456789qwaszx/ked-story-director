# 검증 보고와 「진행 JSON 미출력」이 어긋나지 않게 (R0–R2) — 2026-11-18

**소유자**: 「지금 종종 진행 JSON 미출력이라고 에러를 띄우는데 보고할 것이 없다고 나오는 경우가 많이 있습니다. 실제로 에러가 있고 그것을 다
고쳐서 JSON과 Yarn 출력이 잘 되는데 저 에러 메시지만 남아있는 경우가 있고, 또 그냥 빈 챕터를 띄운경우에는 보고할 것 없이 검증 오류만 저렇게 떠
있습니다. 한번 점검해주시겠습니까?」

> **상태: 진행 중.**

## 1. 지금 — 점검한 것

[구성] 탭의 검증 보고는 **고른 챕터 하나**의 검증(`ChapterExportService.ValidationFor` — 캐시)을 그리고, 맨 위의 결론(「검증 오류로 진행 JSON이
나가지 않았습니다: …」 · 머리의 「🔴 진행 JSON 미출력」)은 **전 챕터의 내보내기**(`ExportAll`)에서 온다. 둘이 갈리는 길이 둘이다(헤드리스로 재현):

1. **다른 챕터가 막혔다** — 결론은 막힌 챕터(예: 방금 만든 빈 챕터 `ch03`)를 말하는데 보고는 고른 챕터(`ch01`)의 것이다. `ch01`의 오류를 다 고쳐
   진행 JSON · Yarn이 잘 나가도 결론은 `ch03` 때문에 남고, 「아래 오류를 고치면」의 그 오류는 아래에 없다.
2. **검증기 밖의 거부** — 빈 챕터는 검증기(`ChapterValidator`)에 오류가 없는데, 내보내기가 낸 JSON을 진행 코어 로더에 실어 보면 거부된다(「시작
   에피소드가 비어 있다」 — `CoreRefusals`). 그 사유는 내보내기 결과에만 붙고 보고가 그리는 캐시에는 없다 → 그 챕터를 골라도 「보고할 것이 없습니다」.

오류를 고친 뒤 결론이 그대로 남는 다른 길(다시 읽기가 안 돈다 · 캐시가 낡았다)은 찾지 못했다 — 고친 순간 다시 내보내고 결론도 걷힌다(시험으로 확인).

## 2. 단계

| # | 일 |
|---|---|
| R0 | 지시서 |
| R1 | **빈 챕터는 막힌 것이 아니다** — 에피소드가 하나도 없는 챕터는 낼 것이 없을 뿐이다: 내보내기가 건너뛰고(파일은 손대지 않는다 — 막혔을 때와 같다) 결론 · 「🔴 진행 JSON 미출력」을 세우지 않는다. 그 챕터의 보고는 「보고할 것이 없습니다」 대신 「에피소드가 아직 없습니다 — 첫 에피소드를 세우면 진행 JSON이 저절로 나갑니다」. 시험 · 문서 |
| R2 | **보고가 막힌 까닭을 다 보인다** — 내보내기가 막은 챕터의 오류(검증기 오류 + 코어 거부)를 내보내기 결과에 싣고(`ChapterExportRun`), 보고는 고른 챕터의 것에 **막힌 모든 챕터의 오류**를 더해 그린다(줄마다 챕터 ID가 앞에 선다). 결론의 「아래 오류」가 늘 아래에 있다. 시험 · 문서 |
