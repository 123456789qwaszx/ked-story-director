# 장면 메모 지시서 (S0–S6) — 2026-11-16

작가가 **장면마다 자유 메모**를 적고, 그 안에 장면의 에피소드 카드를 골라 붙여 **에피소드마다 지시**를 적고,
그것을 대사와 함께 **장면 단위로 내보내는** 일이다.
이 저장소에서는 대본만 다룬다 — 연출(커맨드 · 카드)은 넣지 않는다. 커밋은 S 단위.

## 0. 왜 — 이 메모를 누가 읽나

- 소유자의 목표: 연출 프리셋을 모은 **연출 참고집**(비공개 작업공간 `ked-vn-workspace/catalog/` — 연출 카드 47장)을 AI가 참고해,
  새 비주얼 노벨의 연출을 자동으로 그럴싸하게 붙인다.
- 실제 제작 흐름: 작가가 이 툴로 대본을 쓴다(챕터 → 장면 → 에피소드, 에피소드 = 대사 카드). 그 뒤 **AI가 장면 하나씩** 메모 · 대사 ·
  참고집을 읽고 줄(`LineId`)마다 연출 초안을 낸다. 그 일은 이 저장소 밖(작업공간)에서 한다.
- 참고집으로 다른 장을 예측해 본 시험에서 가장 약했던 것이 "**누구를 세우나**"와 "**표정**"이었다. 대사만으로는 장면에 누가 있는지,
  감정이 어디서 꺾이는지를 알 수 없다 — 작가의 짧은 메모가 그 빈칸을 메운다.
- 그래서 이 일의 산출물은 둘이다: ① 작가가 장면 메모를 쓰는 자리 ② AI가 장면 하나를 통째로 읽을 수 있는 내보내기 파일.

## 3. 메모의 모양 (Q1 정함)

장면마다 메모 공간 하나. 둘로 이루어진다 — 모두 비어도 된다, 쓴 만큼만 쓰인다.

| 자리 | 저장되는 곳 | 무엇을 쓰나 |
|---|---|---|
| 장면 메모 | 챕터의 `sceneNotes[].text`(새 칸) | 작가가 자유롭게 — 이 장면의 사정 전체 |
| 에피소드 지시 | 그 에피소드의 `memo`(있던 칸, 지금 화면에서 고치는 곳이 없다) | 그 에피소드(대사 카드)에만 해당하는 사정 · 지시 |

- **자유 글이다.** 칸을 나누지 않는다. 다만 0절의 빈칸(누구를 세우나 · 표정)을 메우도록, 장면 메모 칸이 비었을 때 **흐린 안내 글**로
  쓸 만한 것을 보인다 — 예: "이 장면이 보여 줄 것 · 인물마다 감정(처음 → 끝) · 감정이 꺾이는 대사 · 무대에 있는 사람 · 장소 · 시간".
  안내일 뿐 형식을 강제하지 않는다.
- **에피소드 카드.** 메모 공간의 [+ 에피소드]는 그 장면의 에피소드 가운데 아직 카드가 없는 것을 고르게 한다. 고르면 빈 지시 칸이 선 카드가
  붙는다. 카드가 있다는 것은 저장되지 않는다 — **지시가 비지 않은 에피소드가 곧 카드**다. 그래서 빈 카드는 다른 곳을 고르거나 다시 열면
  사라지고, 지시를 다 지우면 카드가 빠진다. 카드의 차례는 장면 안 에피소드 차례(하이어아키)다 — 붙인 차례를 저장하지 않는다.
- 작가용 안내(`docs/writer-guide.md` · `docs/작가에게.txt`)에는 "연출을 쓰지 말고 장면의 사정을 쓴다"를 적는다 — 무엇을 어떻게 움직일지는 AI와 연출이 정한다.

## 4. 설계 — 지킬 것

1. **장면을 만들지 않는다.** 장면의 구성원은 지금처럼 `Episode.SceneId` 하나로만 정해진다(계약 §0-0). 장면 메모는 장면에 붙는 **곁 자료**다 —
   구성원 목록 · 순서 · 루트를 저장하지 않는다. 그런 것은 내보낼 때 `ChapterSceneGrouping.Of()`로 계산한다.
2. **열쇠는 `EffectiveSceneId`.** 장면을 안 나눈 에피소드(`__scene_{EpisodeId}`)에도 메모를 달 수 있다.
3. **모델 변경은 `ProjectEditor`만**(§6-5). 장면 메모 · 에피소드 지시 쓰기 · 고치기 · 지우기는 되돌리기 한 단계씩이다.
   에피소드 지시는 있던 `UpdateEpisode(memo:)`로 쓴다 — 빈 글은 "지움"이다(`null`은 지금처럼 "바꾸지 않음").
4. **장면 이름 바꾸기는 메모를 데려간다** — 이름을 바꾸는 같은 편집(같은 되돌리기 한 단계) 안에서 열쇠를 옮긴다(`MainWindow.HierarchyEdit.cs`의 이름 바꾸기 → `ProjectEditor.Chapters`의 장면 지정).
5. **장면 메모를 조용히 지우지 않는다**(§6-9와 같은 생각). 장면 풀기 · 마지막 에피소드 지우기 · 다른 장면으로 합치기로 주인이 없어진 메모는 남고,
   검증이 "주인 없는 장면 메모"로 알린다. 합칠 때 양쪽에 메모가 있으면 받는 쪽 것을 그대로 두고, 보낸 쪽 것은 주인 없는 메모가 된다.
   사람이 지울 수 있는 자리(챕터 인스펙터)를 둔다. 에피소드 지시는 에피소드의 것이라 주인 없는 것이 생기지 않는다 —
   에피소드를 지우면 그 지시도 함께 지워진다(되돌리기로 돌아온다).
6. **진행 JSON(`{챕터}.progression.json`)의 코드는 손대지 않는다.** 런타임 계약이고(§6-12 결정적 출력), 소비자 코어 사본 `src/Ked.Progression`은 고치지 않는다(§6-17).
   장면 메모는 진행 JSON에 나가지 않는다. 에피소드 지시(`memo`)는 지금 코드대로 노드의 `designerNote`로 나간다 — 런타임 DTO에 없는 칸이라 버려진다
   (계약 문서의 걷힌 칸 표). 지시를 쓰면 진행 JSON의 그 칸이 채워지는 것은 받아들인다(Q1a).
7. **결정적 출력.** 저장과 내보내기 모두 같은 입력이면 바이트가 같다. 장면 메모의 차례는 "에피소드 차례에서 그 장면이 처음 나오는 차례", 주인 없는 메모는 그 뒤에 열쇠 차례(서수). 빈 메모(글이 빈)는 쓰지 않는다.
8. **옛 프로젝트는 그대로.** `sceneNotes`가 없는 프로젝트를 열고 저장하면 바이트가 같다(빈 칸을 새로 쓰지 않는다). 모르는 키를 관대하게 읽지 않는다는 §6-8은 그대로다.

## 5. 파일 모양

**저장** — `*.vnproject.json`의 챕터마다:

```json
"sceneNotes": [
  { "sceneId": "교실", "text": "…" }
]
```

모델: `ChapterGraphModel` 층에 `ChapterSceneNote(string SceneId, string Text)`와 챕터의 목록.
읽기 · 쓰기는 `src/Vn.Authoring/Serialization/ChapterDocumentJson.cs`(에피소드의 `memo` · `sceneId`를 읽고 쓰는 자리 옆).
에피소드 지시는 새 저장 칸이 없다 — 에피소드의 `memo` 그대로다.

**내보내기(새 파일)** — `exported/{챕터}.scenes.json`. 진행 JSON과 같은 때(`AutoExport` · `ChapterExportService`) 쓰고, 같은 결정성 시험을 붙인다.

```json
{
  "format": "ked-scenes/1",
  "chapterId": "festival_eve",
  "displayName": "축제 전날",
  "scenes": [
    {
      "sceneId": "교실",
      "displayName": "교실",
      "rootEpisodeId": "Festival_Classroom",
      "note": "…",
      "episodes": [
        { "episodeId": "Festival_Classroom", "title": "교실 - 반쯤 빈 간판",
          "note": "…",
          "lines": [ { "lineId": "ln_kdy67tc8", "speaker": "하린", "text": "좋아, 처음부터 다시. 붓부터 새로 빨아 올게." } ] }
      ]
    }
  ],
  "orphanNotes": [ { "sceneId": "…", "text": "…" } ]
}
```

- 장면의 `note`는 장면 메모, 에피소드의 `note`는 그 에피소드의 지시(`memo`). 비면 칸을 쓰지 않는다.
- `episodes`에는 지시가 없는 에피소드도 모두 든다(장면의 대사 전체가 있어야 하므로) — 메모 공간의 카드 여부와 상관없다.

- `episodes`의 차례는 하이어아키(장면 안 에피소드 차례)와 같다. `lines`는 그 카드 대본의 살아 있는 줄 — 은퇴한 줄은 넣지 않는다.
- `lines`는 Q3이 "넣지 않는다"면 뺀다(그때 AI는 yarn을 따로 받는다).
- 이것은 산출물이다 — 편집 가능한 대사 사본이 아니다(§6-0). 파일 머리에 산출물이라고 적을 칸이 필요하면 `"generatedBy"`를 둔다.

## 6. 화면

- **장면 인스펙터** — 하이어아키에서 장면 줄을 고르면 나오는 자리(`MainWindow.Hierarchy.cs`의 `HierarchyKind.Scene` 갈래, 두 탭이 같은 하이어아키를 쓴다).
  지금은 머리와 "장면 이름은 [구성] 탭에서 고칩니다" 안내와 에피소드 목록뿐이다. 그 위에 메모 공간을 둔다:
  - 장면 메모 — 여러 줄 글 칸 하나, 비었을 때 흐린 안내 글(3절).
  - 에피소드 카드 — 지시가 있는 에피소드마다 카드 하나(머리: 에피소드 제목, 몸: 여러 줄 지시 칸). 그 밑에 [+ 에피소드](아직 카드가 없는
    그 장면의 에피소드를 고른다 — 남은 것이 없으면 흐리게).
  - 다른 인스펙터 칸과 같은 방식으로 반영한다(초점이 떠날 때 · Enter — 여러 줄 칸이라 줄바꿈 키는 정해서 적는다). 값을 넣는 동안의 이벤트를
    입력으로 보지 않는다(§6-11 `_building`).
- **표시** — 장면 메모나 에피소드 지시가 하나라도 있는 장면은 하이어아키의 장면 줄과 연출 그래프의 장면 프레임 이름표에 작은 표시(예: "메모").
  색만으로 알리지 않는다(§6-3). 지시가 있는 에피소드는 [구성] 카드 툴팁에 지금처럼 "메모:"로 보인다.
- **챕터 인스펙터** — 주인 없는 메모가 있으면 목록과 [지우기].

## 8. 하지 않는 것

- Scene 엔티티(구성원 · 루트를 따로 저장하는 표)를 만들지 않는다.
- 연출 커맨드 · 연출 카드 ID · 표정 이름을 메모 칸이나 대본에 넣지 않는다(툴이 막지는 않는다 — 작가 안내로 알린다).
- 장면 메모를 여러 칸(의도 · 감정 · 고비 · 자리)으로 나누지 않는다(Q1).
- 진행 JSON · `src/Ked.Progression` · compositor를 고치지 않는다.
- AI 연출 초안을 만드는 일 — 이 저장소 밖(작업공간)의 일이다. 이 일의 끝은 `scenes.json`까지다.

## 9. 조심할 것

- **원격 셸(VM)에서 git을 쓸 때** `git -c core.autocrlf=true`를 붙인다. 붙이지 않으면 줄 끝 때문에 수십 개 파일이 "바뀜"으로 보인다.
  커밋할 때 git이 잠금 파일을 지워야 하므로 작업 폴더의 삭제 허락이 한 번 필요하다. 커밋 메시지 파일은 `/tmp`가 아니라 세션마다 다른 경로에 쓴다(다른 세션이 남긴 같은 이름의 파일을 읽을 수 있다).
- **견본에 소유자의 커밋 전 변경이 있다**(2026-11-16 기준 `samples/RuntimeSamples/FestivalEve/` — 프로젝트 · 진행 JSON · yarn 등).
  그 파일들을 덮어쓰거나 커밋에 넣지 않는다. 견본으로 손 확인을 할 때는 사본에서 한다.
- 화면 시험은 헤드리스(`Vn.App.Tests`)다. 실제 화면 확인은 소유자가 한다 — S4 뒤에 확인을 받는다.
