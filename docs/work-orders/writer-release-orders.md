# 작가에게 건네기 — 덮어쓰기 막기 · 판 번호 · 안내문 · 릴리스 · Git 차림 (WR0–WR5) — 2026-11-19

**소유자**:
- 「이후에 진짜로 시나리오 작가가 바로 쓸 수 있게 준비를 합시다.」
- 작가의 PC는 **Windows**. 앱은 **GitHub 릴리스**로 건넨다. 작가가 쓴 프로젝트는 **Git(GitHub)** 으로 주고받는다.
- 꾸러미에 **안내문**을 넣는다. 실제 게임 프로젝트는 지금 소유자의 PC에만 있다 — 비공개 저장소는 소유자가 만든다.

앞선 일: `writer-app-orders.md`(WA0–WA9 — 맥 최소 지원 · 트랙패드 · 이름과 아이콘), `usability-orders.md`(UX0–UX32).

## 1. 지금 · 정한 것

| # | 지금 | 정한 것 |
|---|---|---|
| 덮어쓰기 | 앱은 연 뒤에 프로젝트 파일이 바뀌었는지 보지 않는다. Git으로 주고받으면 작가가 앱을 켜 둔 채 GitHub Desktop으로 **받기(Pull)** 할 수 있는데, 그러면 다음 저장 · 10분 자동 저장이 **받은 것을 말없이 덮는다**(되돌리기 기록에도 없다) | **바깥에서 바뀐 프로젝트를 덮지 않는다**(WR1). 열 때 · 저장한 뒤에 목차와 판 파일의 내용 지문을 찍어 두고(`ProjectDiskStamp`), 창으로 돌아올 때 견준다 — 여기서 고친 것이 없으면 그대로 다시 읽고(상태줄로 알린다), 있으면 **위 띠**가 [다시 열기(여기서 고친 것 버림)] · [내 것으로 덮어쓰기]를 고르게 한다. 고를 때까지 저장 · 자동 저장은 쓰지 않는다. 창을 띄우지 않는다(Ctrl+S에는 붙을 자리가 없고, 띠는 판을 덮지 않는다) |
| 판 번호 | 앱 어디에도 판 번호가 없다 — 작가가 「안 돼요」라고 할 때 어느 판인지 모른다. 맥 꾸러미만 굽는 날짜를 번호로 단다 | 꾸러미를 구울 때 정한 판 번호를 **창 제목**에 단다(「스토리 디렉터 0.1.0 — 프로젝트」). 손으로 짓는 개발 빌드는 「개발판」. 꾸러미 이름에도 번호 (WR2) |
| 안내문 | 꾸러미는 실행 파일 하나뿐이다(2026-08-26 소유자 — 그때의 안내문 · 견본이 낡아서). `docs/작가에게.txt`는 그 뒤로 고쳐 왔다 | 꾸러미에 **「먼저 읽어주세요.txt」**(= `docs/작가에게.txt`)를 넣는다 — Windows · 맥 (WR3). 견본 프로젝트는 넣지 않는다 — 실제 프로젝트는 Git으로 받는다 |
| 건네기 | Windows 꾸러미는 CI가 구워 켜 보고 버린다. 맥 꾸러미만 Actions 결과물로 남는다(로그인한 사람만 받는다) | **GitHub 릴리스**(WR4) — Actions의 「release」를 [Run workflow] → 판 번호(예 `0.1.0`) → Windows · 맥 꾸러미를 굽고 시험을 돌린 뒤 `v0.1.0` 릴리스에 둘을 올린다. 소유자가 거기서 받아 작가에게 건넨다(저장소가 비공개라 작가는 릴리스 페이지에 못 들어간다) |
| 프로젝트 저장소 | 없다 — 실제 프로젝트는 소유자의 PC에만 있다 | 소유자가 **비공개 저장소**를 만들고 프로젝트 폴더를 올린 뒤 작가를 초대한다. 이 저장소에 둘 `.gitignore`(`exported/` · `runtime.target.json` — 저장마다 다시 내는 것 · 이 PC의 보낼 곳)와 `.gitattributes`(JSON · Yarn은 LF)를 견본으로 둔다. 작가는 **GitHub Desktop**으로 받고(Clone) · 쓰고 · 올린다(Commit · Push) — 안내문에 그 절을 더한다 (WR5) |

하지 않는 것: 코드 서명(Windows의 「PC 보호」 창은 안내문대로 한 번 지난다), 자동 업데이트, 설치 프로그램, 앱 안의 Git 단추, 두 사람이 같은 파일을 동시에 고친 것의 합치기(Git의 충돌은 「한 사람씩 · 받고 시작 · 끝나면 올리기」로 피한다 — 안내문).
