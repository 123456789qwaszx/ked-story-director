**소유자**: 「조건 공급 노드라는 게 뭐야? 그건 엄청 예전에 지웠잖아.」 → (설명 — 11-18 old-shapes O6에 작가용 설정 노드를 걷을 때 다리로 하나 남겼다) →

> **상태: 0.4.0 — 시작 전.** 견적과 할 일의 안만 적었다. 0.3.0은 그대로 낸다.

## 1. 지금

- **조건 공급 노드** — 챕터마다 툴이 저절로 만드는 숨은 설정 노드(`ChapterBoardSupply` · 이름 「챕터 {챕터ID} 조건」). 챕터 조건의 사본(조건 ID ·
  이름 · Yarn 식)을 든다. 분기 카드 첫머리의 `<<if>>`가 그 사본의 조건 ID(`cd_…`)를 가리키고, Yarn의 `<<if stat("…") …>>`가 그 식에서 나온다.
  판 · 하이어아키에 보이지 않고, 작가가 만들거나 지우지 않는다.
- **왜 있나** — 대사 카드의 `<<if>>`는 「이야기 그래프 안 설정 노드의 조건」을 가리키는 짜임이다. 챕터 조건이 [구성] 탭의 정본이 된 뒤 둘을 잇는
  다리로 이 사본을 두었고, 작가용 설정 노드를 걷을 때(11-18 O6) 이것만 남았다.
- **들이는 값** — 같은 것이 두 벌이라 코드가 맞춘다(v0.2.0 직전의 두 버그 — 식을 고쳐도 글 칸의 `<<if>>`가 옛 식에 머문 것 · 아직 없는 스탯을
  적은 식의 사본이 옛 식에 머문 것 — 가 여기서 났다). 판에서 숨기기 · 열 때 「판마다 이 이름의 설정 노드 하나」만 받기 · 이름으로 찾기가 약 15개
  파일에 흩어져 있다. 이름이 곧 신원이라 언어마다 바꿀 수 없다.
- **영어 화면에 남은 한국어 둘**(english-ui E8) — ① 이 노드의 이름(프로젝트 파일 안 · 화면에 안 보인다) ② 진행 코어(`Ked.Progression`)의 거절
  문장 — 검증 보고 *The progression core can't load this chapter — (코어 문장)*의 괄호 안. 이쪽 검증이 같은 규칙을 먼저 짚어 드물게만 보인다.

## 3. 시작할 때 물을 것

- **옛 프로젝트** — 0.3.0까지 저장한 파일의 공급 노드를 열 때 풀어 옮길지(조건 ID → 조건 이름 · 노드를 버린다), 거절할지. 11-18(old-shapes)에는
  「옮기기 없이 거절」이었지만, 지금은 작가가 0.2.0 · 0.3.0으로 쓴 프로젝트가 있다.
- **코어 문장의 「영어로」** — 영어 한 벌로 바꿀지, 두 언어로 둘지. 코어는 게임(런타임)의 로그에도 쓰인다.
- **0.3.0과 섞어 쓰기** — 0.4.0이 저장한 프로젝트(공급 노드 없음)를 0.3.0이 열면 어떻게 되는지 보고 릴리스 노트에 적는다.
