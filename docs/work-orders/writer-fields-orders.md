# 작가 칸 지시서 (W0–W6) — 2026-11-16

`display-names-orders.md`와 같은 원칙을 화자 · 조건 · 스탯에 넓힌다: **[대본] 탭은 작가가 생각하는 단위(이름 · 뜻 · 키)를 더하고 고치고,
[구성] 탭은 그 세부(캐릭터 키 · 조건 식 · 스탯 범위)를 정한다.** 커밋은 W 단위, 이 저장소의 관행대로(작성자 Claude · 표시 줄 · `dev`에 로컬 커밋만).

## 1. 정한 것 (소유자 2026-11-16)

| | 내용 |
|---|---|
| 화자 | [대본]에서 화자 **이름**을 더하고 고친다. **캐릭터 키**는 [구성]에서 정한다 |
| 조건 | [대본]에서 조건 **라벨**(뜻 — 「하린과 친해졌을 때」)을 더하고 고친다. **식**(`trust >= 3`)은 [구성]에서 정한다 |
| 식이 빈 조건 | **오류가 아니다** — 경고만 하고 「식 미정」으로 내보낸다. 작가가 먼저 쓰고 개발자가 나중에 채우는 흐름을 막지 않는다 |
| 스탯 | **키만** 있다 — 표시 이름 칸을 걷는다. 게임 화면에 보일 글자는 게임 쪽이 키로 로컬라이즈한다(작가가 정할 것이 아니다). 대사에 쓰는 글 `{stat("키")}`의 따옴표 안은 키다(지금도 그렇다) |
| 화자를 더하는 곳 (답) | **[대본]에서 더한다** — 2026-08-23의 「화자는 [화자] 탭에서만 · 작가가 더한 화자는 없앤다」 결정을 소유자가 바꿨다. 집은 그대로 `game.definition.json`의 speakers 하나 |
| 스탯을 더하는 곳 (답) | **[구성]에서만** — 스탯은 세이브 열쇠 · 범위와 한 몸이라 개발자가 만든다. [대본] 챕터 요약은 지금처럼 표(키 · 범위 · 대사에 쓰는 글 · [복사])만 보인다. W5는 걷는다 |

## 2. 설계 — 지킬 것

1. **식 미정 = 항상 통과.** 식이 빈 조건은 관문이 없는 것과 같다 — 판정(`ChapterGateJudge`)은 열림, 도달성 증명도 그렇게 본다.
   진행 JSON은 이미 빈 조건 배열을 낸다(모양 그대로). 진단 `ConditionExpressionBlank`는 **경고**로 낮추고 「식 미정 — 항상 통과합니다」라고 말한다.
   식이 **틀린** 것(모르는 스탯 키 · 문법)은 지금처럼 오류다.
2. **스탯 표시 이름을 걷는다.** 모델 · 화면에서 뺀다. 진행 JSON의 `Stats[].DisplayName`은 키를 그대로 낸다(계약 모양 그대로).
   옛 파일의 스탯 `displayName`은 읽지 않고 지나간다(걷힌 칸의 규칙 — ARCHITECTURE §8), 저장할 때 쓰지 않는다.
   `game.definition.json`의 변수 설명을 표시 이름에서 채우던 길도 걷는다(이미 적힌 설명은 남긴다 — 모르는 키 보존 §6-16).
3. **[대본] 탭에서 더하고 고치는 것** — 화자 이름(프로젝트 줄 요약), 조건 라벨(챕터 줄 요약). 이름 바꾸기는 쓰이는 곳이 따라간다:
   화자는 `RenameSpeaker`(대본의 화자 글자), 조건은 새 `RenameChapterCondition`(간선의 표시조건 · 해금조건 · 분기 조건 라벨).
   (스탯 키는 [구성]에서만 더한다 — 1절의 답.)
4. **[구성] 탭에서 정하는 것** — 화자의 캐릭터 키, 조건의 식, 스탯의 종류 · 처음 값 · 범위. [구성]에서 이름(라벨 · 화자 이름)을 더하는 칸은 걷는다.
   스탯 키 바꾸기(✎)는 [구성]에도 남긴다 — 세이브 열쇠라 개발자가 정리할 일이 있다(소유자에게 확인).
5. 모델 변경은 `ProjectEditor`(화자는 세션의 정의 파일 쓰기)만, 되돌리기 한 칸씩.
