# 지운 챕터의 판 파일을 저장할 때 걷는다 (SF0–SF2) — 2026-11-18

**소유자**: 「확인하다 찾은 문제만 고쳐줘.」 — 챕터를 지운 뒤 저장해도 그 챕터의 `story/sf_….vnstory.json`이 남는다(2026-11-18 · 「sf_c5irt5ve.vnstory는 뭐야?」를
살피다 찾았다).

> **상태: 끝 (2026-11-18).**

## 1. 지금

- 저장(`ProjectStore.Save`)은 지금 있는 판의 파일만 쓰고 목차(`project.vnproject.json`)를 마지막에 쓴다.
- 목차에서 빠진 판 파일(지운 챕터의 판)은 지우지 않는다.
  - 목차가 가리키지 않으니 읽히지는 않는다.
  - 챕터를 만들었다 지울 때마다 `story/`에 쓰지 않는 파일이 쌓이고, 사람은 어느 것이 쓰이는지 알 수 없다.

## 2. 정한 것

- **저장이 끝난 뒤(판 파일 · 목차를 모두 쓴 뒤) 목차에서 빠진 판 파일을 지운다.**
  - 지우기가 쓰기보다 뒤라, 중간에 꺼져도 남는 것은 쓰지 않는 파일뿐이다. 목차가 가리키는 파일이 사라지는 일은 없다.
- **지우는 것은 툴이 지은 것만이다.**
  - 자리는 프로젝트 폴더의 `story/` 바로 안이다.
  - 이름은 `sf_` + 툴의 ID 글자 8자 + `.vnstory.json`이어야 한다(`Identifier.File`의 모양).
  - 사람이 복사해 둔 파일(「sf_… - 복사본.vnstory.json」) · 다른 이름 · 하위 폴더는 건드리지 않는다.
- **폴더에 다른 프로젝트 파일(`*.vnproject.json`)이 있으면 지우지 않는다.** 두 목차가 `story/`를 함께 쓰는 옛 배치에서 남의 판을 지우지 않게
  한다(그런 폴더는 열 때 이미 거절된다 — `ProjectFolder.Find`).
- 지우지 못한 파일(잠김 · 권한)은 그냥 남긴다 — 저장은 이미 끝났고, 다음 저장이 다시 본다.
- 되돌리기와는 상관없다.
  - 지운 챕터를 되돌리면 그 판은 메모리에 있으므로 다음 저장이 다시 쓴다.
  - 저장한 뒤에 되돌려도 마찬가지다.
