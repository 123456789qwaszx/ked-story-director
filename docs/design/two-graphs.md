### 2.2 사용자 동작

모든 편집은 `ProjectEditor`를 지나고 되돌리기는 프로젝트 스냅샷이다. Ctrl+Z/Y/S는 창 전역이고, **글자 칸에 초점이
있으면 Z/Y를 가로채지 않는다**(`MW` 254-287). Delete 키 · Esc · F1 · 판의 우클릭 메뉴는 없다.

| 동작 | 결과 |
|---|---|
| 카드 클릭 / 끌기 | 선택 / 끄는 동안은 화면만, **놓을 때 `MoveEpisodes` 한 번**(되돌리기 한 칸) |
| 카드 더블클릭 | 대본 엑셀을 연다(없으면 만든다) — D2에서 걷는다 |
| 휠 / 가운데 단추 끌기 | 커서 기준 확대(0.3~2.5) / 판 이동 |
| 선 · 문구 · 점 클릭 | 간선 패널. 분기 점선 클릭은 분기 패널 |
| [＋ 에피소드] | `new01…` 발급. 고른 것(없으면 마지막)의 다음으로 `AddNextEpisode` — 에피소드 · 카드 · 대본 · 간선(문구 `계속`)이 **한 Mutate** |
| [자동 정렬] | **연출 그래프의 카드 자리를 본떠**(`ChapterBranchPlanner.LayoutLikeBoard` — 연출의 열 320 → 옆 220, 줄 400 → 170으로 줄이고, 줄여서 부딪치면 왼쪽 이웃의 오른쪽으로 비킨다. 연출 그래프에 카드가 없는 에피소드는 맨 아래 줄. 2026-10-30) `MoveEpisodes` 한 번으로. 연출 그래프에 카드가 하나도 없으면 흐름 순서(`Layout`) |
| [에피소드 삭제] | 끝점 간선 · 픽스처 참조 · 카드까지 함께 걷는다 |
| 이름 칸 Enter | 에피소드 개명 — 간선 · 픽스처 · 카드 이름이 따라간다. `cleared:` 참조가 있으면 거부 |
| 선택지 [＋] · 줄 클릭 · [잇기]/[수정] · ✕ | 한 줄 폼을 열고 닫는다 · `AddEdge`/`SetEdgeRoute`(순서를 지킨다) · `RemoveEdge`(문구 사전은 남는다) |
| 간선 패널의 콤보 | 고르는 즉시 `UpdateEdge`. 글자 칸(잠금 안내문 · 스탯 수치)은 초점을 잃거나 Enter일 때 |
| 분기 조건 콤보 | `SetEntryCondition` — 첫 줄 `BeginIf` + 꼬리 `EndIf`를 한 Mutate로. 손으로 지은 구조면 칸이 잠기고 사유를 말한다 |
| [챕터] 조건 · 스탯 | 식 · 표시이름 · 범위 · 타입. 스탯 키는 ✎로만(세이브 열쇠라 경고를 먼저). 지울 때 쓰는 곳이 있으면 목록을 보인다 |

### 2.3 배치

- 자리의 주인은 에피소드의 X·Y다(v4, 2026-09-18). 그리기는 그 값을 덮지 않는다. 카드가 한 점에 포개져 있을 때만
  `Layout`을 **빌려** 보이고, 첫 끌기 때 판 전체 자리를 함께 적는다.
- 포트(v5): **선택지는 아래, 분기는 옆(다녀갈 카드 쪽), 들어오는 길은 위 가운데 점 하나.** 연출 그래프와 손놀림을 맞춘 것이다.
- [자동 정렬]은 연출 그래프의 모양을 본뜬다(2026-10-30 소유자: *"연출 그래프에 배치된 노드들을 참고해서 그와 거의 같은
  형태로"*). 흐름 순서 배치(`Layout`)는 첫 심기와 연출 그래프에 카드가 없을 때 쓴다.
- 흐름 순서 배치와 새 카드 자리(`SuggestPlacement`)는 깊이를 **Y축**(줄 170 · 옆 220)으로 편다 — 포트와 같은 위→아래다
  (D3-a). ⛔ D3 전에는 깊이가 X축이라 포트는 위→아래인데 자동 배치만 왼→오였고, 소유자 화면의 위→아래는 사람이
  끌어 놓은 것이었다.

### 2.4 검증 · 내보내기

- 프로젝트가 바뀔 때마다 재읽기가 한 UI 차례에 한 번으로 합쳐 돈다: 전 챕터 진행 JSON 자동 내보내기 → 고른 챕터 검증 →
  그리기(`CGV` 1139-1176, 379-393).
- 검증 = 모델 진단(스탯 범위 · 조건식 · 자동 길 · 장면 입구) + 판에 대사 노드가 있는가 + 줄 없는 노드 + 도달성 증명
  (상태 상한 250,000, 다 못 훑으면 오류가 아니라 알림). 증명은 모델 내용으로 캐시한다(VnTool C3).
- 내보내기는 검증을 통과한 챕터만, 진행 코어 로더에 실어 본 뒤, 바이트가 다를 때만 `exported/{챕터}.progression.json`에
  쓴다. 출시 기준선 대비 선택지 순서가 바뀌면 막는다.

### 3.1 화면 · 노드

| 자리 | 무엇 |

| 툴바 | 챕터 콤보(챕터 그래프와 짝) · [＋ 대사 노드] · [노드 삭제](에피소드 카드를 고르면 **[에피소드 삭제…]**로 바뀐다). ⛔ [자동 정렬] · 필터 [대사][설정]은 2026-10-29에 걷혔다(E1) |
| 판 | 캔버스 12000×8000. 펼친 판마다 **챕터 프레임**(이름표를 누르면 표로 접힌다), 장면이 둘 이상이면 **장면 프레임**(진입점이 둘이면 ⚠). 우하단 미니맵과 [전체/50/100/150] |

| 노드 | 모델 | 카드 |
|---|---|---|
| **에피소드 카드** | 챕터 판의 `DialogueNode`(+`MarkedEpisodeId`). 챕터 판의 대사 카드는 전부 에피소드다(R7) | 📄 미색. 머리는 제목 한 줄 = 이름(= EpisodeId)(⛔ 부제 `대사 · 에피소드 · {대본} · k줄`은 M에 걷혔다). 카드 안 오른쪽에는 IF 갈래 포트, 그 아래 **글 칸**(D4 — §3.4) — **분기 점은 글 칸에서 그 대사 옆 · 카드 가장자리**에 선다. 한 대사(의 같은 쪽)에 분기가 둘 이상이면 **분기 수를 적은 공통 점 하나로 접히고** 선들도 거기서 나간다 — 공통 점을 누르면 가지가 갈라져 개별 점들이 카드 밖에 세로로 서고(18 간격 — 겹치지 않는다), 선은 제 점에서 나가며 그 점을 끌어 다시 잇는다. 다시 누르면 접힌다(2026-10-30 — 펼친 상태는 판을 다시 그려도 남고 저장하지 않는다. 칸 밖으로 스크롤된 대사면 칸 끝에 흐리게 붙는다. ⛔ 같은 날 오전의 분기마다 대사 위에 끼던 빈 줄은 걷혔다), **카드 아래에는 선택지 칸**(최소 3) |
| 낙서판 카드 | 챕터가 아닌 판의 `DialogueNode` | ✎ 흰색. IF · 선택 · `기본` 포트와 글 칸(분기 점은 그 대사 옆, 여럿이면 공통 점으로 접힌다). 선택지 칸 · 레일 없음 |
| 숨은 설정노드 | `SetNode` 전부 — 조건 공급 배관과 옛 판의 「{챕터} 설정」 | 그리지 않는다(`GraphProjectionBuilder.IsHiddenPlumbing`). 그래도 `board.Nodes`에는 있고 안의 조건은 대사의 조건 목록에서 고른다. ⛔ 판마다 「{챕터} 설정」을 세우던 일은 L6에 그쳤다 — 안을 채우던 편집기가 먼저 걷혀 빈 카드였다. 숨은 연출 노드 · 명령 공급 노드는 compositor로 갔다 |

### 3.2 사용자 동작

| 동작 | 결과 |
|---|---|
| [＋ 대사 노드] | 화면 가운데에 선다. 챕터 판이면 **에피소드도 함께** — 노드 · 대본 · 빈 첫 줄 · 에피소드가 한 Mutate |
| 카드 클릭 · 끌기 · 고무줄 | 선택 / 끄는 동안은 화면만, **놓을 때 `MoveNodes` 한 번**(되돌리기 한 칸 · D3-d1, §6-2) / 무리 선택 |
| 카드 더블클릭 | 아무 일도 없다. ⛔ 무대 프리뷰 탭으로 가던 길(자동 발행 · 숨은 연출 노드)은 무대와 함께 compositor로 갔다 |
| 선택지 칸 글자 클릭 | 글자 칸이 열린다. Enter 확정 · Esc와 초점 이탈은 취소. 빈 칸의 문구는 **저장하지 않고** 차례로 들고 있다가 이을 때 쓴다 |
| 선택지 점 → 다른 카드 | `AddEdge`(문구가 없으면 자동 길). 다른 챕터 · 장면을 넘는 자동 길은 말로 거부. 이미 이어진 칸을 옮기면 `SetEdgeRoute` — 목록의 자리 · 관문 · 스탯 변화를 지키고 되돌리기 한 칸(D3-d3, §6-3). 같은 카드에 도로 놓으면 아무 일도 없다 |
| 선택지 점 → 빈 곳 | 길을 걷고 문구는 빈 칸 차례 맨 앞으로 |
| 카드 안 IF·분기 포트 끌기 | `SetExitTarget`. 빈 곳에 놓으면 연결을 끊는다(분기면 표식이 지워진다) |
| 간선 클릭 / 우클릭 | 선택(힌트 띠에 정체) / **삭제**. 분기 선의 삭제는 「분기 지우기」다 — 표식과, 분기가 다녀가던 에피소드를 함께 걷는다(E2) |
| 곁기둥 | 이름 초점 이탈 → 개명(에피소드 카드는 읽기 전용) · [줄 추가] · 화자/대사 **글자마다 `SetScriptLineText`** · ＋ 플라이아웃(「＋ 분기 추가」 — 분기가 있어도 서고 새 분기는 그 뒤에 선다, 분기마다 「✕ '이름' 분기 지우기」 · 조건 · ▲▼✕). 줄 앞에는 분기 카드가 다녀오는 차례로 쌓인다(`분기 1/2`). 분기 카드의 색은 연출 그래프 카드의 그 분기 포트 · 선의 색이고, 카드를 **우클릭**하면 그 분기를 지운다(2026-10-30) |

### 3.3 배치 — 위→아래 (D3 · 2026-10-29)

- 저장되는 것은 노드마다 `Layout{X,Y}` 하나다. 프레임 · 장면 영역 · 레일 · 포트는 그릴 때마다 계산한다.
- **새 카드 자리는 `NodePlacement.For` 한 벌**이다(`src/Vn.Authoring/Graph/NodePlacement.cs`, 열 320 · 줄 400 — 글 칸이 선 D4부터).
  선택지로 가는 다음 에피소드는 **부모 카드 아래**(합류하면 가장 아래 부모의 밑), 그 자리가 차 있으면 오른쪽으로
  비켜 선다. 부모가 없으면 판의 맨 아래 카드 밑, 판이 비었으면 원점이다. ⚠ 이미 선 카드는 옮기지 않는다.
  ⛔ D3 전에는 장면마다 한 줄을 받고 장면 안의 진행이 그 줄의 오른쪽으로 갔다(maxX + 320, 장면 차례 × 260).
- 「분기 추가」의 새 카드는 원본의 **오른쪽**(`NodePlacement.BesideOf`)에 선다 — 이미 분기가 있으면 같은 열의 아래로 쌓인다(2026-10-29 · 한 줄에 분기 여럿). ⛔ D3 전에는 바로 아래(Y + 260).
- ⛔ 판 전체를 다시 세우던 [자동 정렬](`NodePlacement.Arrange`, D3-d2)은 2026-10-29에 걷혔다(E1 · 소유자: *"자동 정렬과
  필터가 있는데, 둘다 필요없으니 지워주십시오."*). 이미 선 카드는 사람이 끌어 옮긴다.
- 레일(챕터 간선): 줄기가 카드 **가운데**에서 아래로 내려가고 칩(선택지 칸)이 세로로 쌓인다(M — 그 전에는 왼쪽+30). 레인은 칩 오른쪽으로
  나와 **아래로** 내려가 도착 카드 **위 가운데**의 접점으로 들어간다. ⛔ D3 전에는 가로 레인이 도착 카드의 왼쪽
  접점으로 들어갔다. 실행 간선(IF 갈래 · 분기)은 그대로 카드 오른쪽 포트 → 도착 카드 왼쪽, 가로-세로-가로
  직교선이다(`OrthogonalEdgeRouter`). 챕터 · 장면 프레임은 카드 아래 레일까지 감싼다.
- 끌기: 끄는 동안은 투영의 자리만 바꿔 다시 놓고(`PreviewDrag`), 놓을 때 `MoveNodes` 한 번(`CommitDrag`)이다.
  더블클릭의 첫 누름이 시작한 끌기는 걷고 화면을 프로젝트 자리로 되돌린다(`CancelDrag`).

### 3.4 대사 본문이 카드에 닿는 길 — 카드 안 글 칸 (D4 · 2026-10-29)

- 노드는 제 대본(`Script`)을 들고, 그 위에 LineId에 붙는 논리(갈래 · 분기 표식)를 든다(2026-10-29 S2 전에는 따로 선
  대본을 `ScriptId`로 가리켰다).
- **대사 카드마다 글 칸이 있다**(포트 줄 아래, 높이 88 · 다섯 줄 남짓, 넘치면 칸이 스크롤). 보이는 글은
  `WorkingDialoguePreview.ScenarioText` — ScenarioOnly 표기(조건은 Yarn 문법 `<<if>>`) 그대로이되 진단 줄은 뺀다.
  한 줄이 대사 한 줄이고 `화자: 대사`(화자가 없으면 지문)다.
- **쓰는 대로 들어간다**(2026-10-30 소유자: *"에피소드 노드 속의 텍스트 편집하는 게 그대로 반영이 바로바로
  되기를"*) — 치다가 0.4초 멈추면 칸을 나오지 않아도 넣고(`CommitLiveWriting`), 곁기둥이 곧바로 따라온다. 이 넣기는
  **줄을 지우는 글은 넣지 않는다**(`confirmDeletes: false`) — 다 지우고 새로 쓰는 도중의 모습에서 줄을 은퇴시키면 그
  줄의 분기 · 연출이 떨어져 나가고, 은퇴한 신원은 되살리지 않는다. 못 넣어도 칸을 붉히지 않는다(아직 쓰는 중이다).
- **줄을 지우는 것까지 다 넣는 때는 초점을 잃을 때와 Ctrl+S**(저장 · 다른 이름으로 저장이 먼저 넣는다). 카드 머리나
  빈 판을 누르면 칸의 초점을 놓아(`WritingFocusSink`) 다른 노드를 고르기 전에 넣는다. 넣기는 초점이 다 옮겨 간 뒤로
  미뤄 부르고, 판을 다시 그리면 초점 · 커서를 그 노드의 새 칸으로 돌려준다(넣지 않은 글이 있었으면 그 글도). 판에서
  떼어 낸 옛 칸의 초점 이탈은 넣지 않는다. 다 넣은 뒤 칸은 도구의 표기로 다시 선다.
- **고친 줄은 처음 보인 줄의 신원을 잇는다**(2026-10-30 — 소유자 보고: 기존 글을 지우고 새로 쓰면 *"찾을 수
  없다"*고 거절). 칸의 글에는 LineId가 안 보여 동기화가 내용만 보고 짝을 맞췄고, 한 구간에서 두 줄 이상을 고치면
  확신 없는 짝으로 통째로 거절했다. 이제 넣기 전에 마지막으로 보인 글(`ScenarioWritingLayout.RowOfLine`)과 고친 글을
  줄 단위로 견줘(`ScenarioLineIdentity.CarryLineIds` — 같은 줄은 그대로, 사이의 고친 구간은 같은 자리끼리) 줄 끝에
  `#line:` 표지를 붙여 넘긴다. 줄을 고치면 그 줄이고, 지우면 은퇴하고, 새로 쓰면 새 줄이다.
- 넣는 길은 `ApplyScenarioText(…, strict: true)` 하나다 — diff로 **LineId를 지키고**(§5-2) 넣기 한 번이 되돌리기 한
  칸이다(`Batch`). **엄격하다**: 해석 못 한 줄 · 못 세운 조건 · 확신 없는 짝이 하나라도 있으면 아무것도 안 넣고, 글을
  칸에 둔 채 칸을 붉게 하고 사유를 풍선과 상태줄에 보인다. 지운 줄은 칸을 나올 때 확인 없이 은퇴한다(되돌리기 한
  번이면 돌아온다). Esc는 안 넣은 글을 버린다. 칸을 눌렀다 나오기만 했으면 아무것도 안 적는다.
- 새 카드는 빈 줄 하나를 들고 선다 — 살아 있는 줄이 빈 줄 하나뿐이면 그 줄이 새 글의 첫 줄이 된다.
- 칸 안의 손짓은 카드와 판이 가로채지 않는다: 누르기는 끌기를 시작하지 않고, 휠은 판을 확대하지 않는다.
- 곁기둥(줄마다 칸, 글자마다 `SetScriptLineText`)도 그대로 있다. 곁기둥에서 고친 글은 `DialogueContent`라 판을
  다시 그리지 않지만 고른 노드의 글 칸은 다시 채운다(쓰는 중이거나 안 넣은 글이 있으면 그대로 둔다). 카드에서
  넣은 글도 **글자만 바뀌었으면**(줄이 생기거나 빠지거나 옮겨지지 않았다) `DialogueContent`라 판을 다시 그리지 않아 쓰던
  칸이 흔들리지 않고, 곁기둥은 그 안에서 쓰는 중이 아니면 다시 선다(2026-10-30). 줄이 생기거나 빠지면 `Structure`다.
- 갱신 계획(`ProjectRefreshPlanner`): `DialogueContent`는 그래프를 다시 그리지 않는다. `Structure` · `Connections` 등은
  `Graph.Rebuild`가 판을 비운다 — 글 칸은 위의 초점 되돌리기로 견딘다.

## 5. 다시 쓸 때 지킬 것

### 데이터

1. **각 값의 주인은 한 곳이다.** 같은 사실이 두 곳에 있으면 어긋나고, 어긋남은 최종 출력에서야 드러난다. 창구가
   둘인 것은 괜찮다(간선) — 사본이 둘인 것이 안 된다.
2. **LineId는 영구 불변이다.** 세이브 · 연출 바인딩 · 번역이 걸려 있다. 글을 다시 넣을 때는 diff로 신원을 잇고, 확신이
   없으면 거부한다. 줄을 지우면 은퇴시키고, 은퇴하면 그 줄의 분기 표식도 접힌다.
3. **간선 순서 = 화면 순서 = 런타임 `OptionIndex`.** 출시된 선택지 사이에 끼우거나 옮기면 과거 플레이 이력의 뜻이 바뀐다.
   이어진 칸을 옮길 때는 순서를 지키는 `SetEdgeRoute`를 쓴다.
4. **스탯 키는 세이브 열쇠다.** 고치는 칸을 두지 않고, 바꿀 때는 경고를 먼저 보이고 쓰는 곳을 함께 끌고 간다.
5. **계산은 저장하지 않는다.** 포트 · 레일 · 프레임 · 검증 · 도착 스탯은 매번 계산한다.
6. **분기 조건은 툴이 아는 모양(첫 줄 `BeginIf` + 꼬리 `EndIf`)만 쓴다.** 손으로 지은 구조는 읽기만 한다.

### 편집 · 되돌리기

7. **사용자 동작 하나 = `Mutate` 하나 = 되돌리기 한 칸.** 둘로 쪼개면 한 번 물렀을 때 반쪽이 남는다(분기 조건이 실사례).
   끌기는 놓을 때 한 번만 적는다.
8. **바뀐 것이 없으면 Mutate하지 않는다.** 같은 값의 Mutate가 화면을 다시 만들어 쓰던 칸을 부쉈다(2026-08-24).
9. **글자 칸은 초점을 잃거나 Enter일 때 넣는다.** 자판마다 넣으면 되돌리기와 재계산이 폭주한다(카드 글 칸은 치다가
   멈출 때도 넣는다 — 자판마다가 아니라 멈춤마다이고, 글자만 바뀐 넣기는 판을 다시 그리지 않는다. §3.4). 저장은 안 넣은 글을
   먼저 밀어 넣는다(D2 전에는 `MW.FlushPendingEdits`가 대본 탭을, 지금은 `GraphEditorView.FlushWriting`이 카드 글 칸을).
   자동 저장은 쓰는 중인 칸을 건드리지 않는다 — 쓰다 만 글을 넣으면 거절되거나 반쪽이 들어간다.
10. **패널을 채우는 동안은 자동 저장을 막는다**(`_fillingPanel`). 화면을 그리는 일이 저장을 부르면 아무것도 안 고쳤는데
    파일이 써진다.
11. **되돌리기는 스냅샷을 새로 푼다.** 들고 있던 노드 객체는 낡으니 Id로 다시 찾는다.

### 화면

12. **내용 변경과 구조 변경을 구분해 알린다.** 글자 편집이 편집 칸을 다시 만들면 안 된다(`ProjectRefreshPlanner`).
13. **클릭 처리기 안에서 판을 다시 만들지 않는다.** 더블클릭과 끌기가 죽는다.
14. **이미 선 카드는 옮기지 않는다.** 자리는 사람이 정한다. 새 카드의 첫 자리 규칙은 한 벌로 둔다. (연출 그래프의
    [자동 정렬]은 2026-10-29에 걷혔다 — 챕터 그래프의 [자동 정렬]은 남는다.)
15. **챕터 선택은 한 길로 지난다.** 드롭다운만 다른 길로 가던 때 검증이 이전 챕터의 것으로 남았다.
16. **재읽기는 합친다.** 동기화 한 번에 재읽기 123번, 첫 화면 58초였다. 고정도 시간이 아니라 일의 횟수로 건다.
17. **떼는 길이 있어야 한다.** 닫힌 뷰의 타이머가 죽은 디스패처에 Post하면 프로세스가 내려간다.
18. **삭제 단추는 늘 같은 자리에 있고, 무엇을 지우는지 이름으로 말한다.** 우클릭으로는 지우지 않는다(연출 그래프의 간선
    우클릭 삭제가 유일한 예외다).
19. **조용히 버리지 않고, 추측으로 고쳐 주지 않는다.** 못 그린 것은 보이게 남기고, 오타는 그 자리에서 오류로 말한다.
20. **잘된 일은 조용하다.** 상태줄 · 검증 보고는 문제가 있을 때만 말하고, 잠금 같은 상태가 그대로면 같은 말을 되풀이하지
    않는다.

### 출력 · 검증

21. **결정적 출력이 계약이다.** 같은 입력은 바이트가 같아야 한다(서버가 SHA-256으로 버전을 식별). 컬렉션 순서를 바꾸는
    리팩터링에 주의한다.
22. **소비자의 실제 코드에 실어 본다.** 진행 JSON은 진행 코어 로더에 통과해야 나간다(게임용 Yarn은 compositor가 실제
    컴파일러에 통과시킨다).
23. **진행 스탯을 Yarn 변수로 읽지 않는다.** 도달성 증명 밖에 숨은 분기가 생긴다.

> *"대본탭과 엑셀 연동 기능은 완전히 제거합시다. 차후에 추가해야 겠지만, 당장은 복잡하기만 합니다."*

### D3 — 연출 그래프를 위→아래로

> *"챕터 그래프처럼 위에서 아래로 진행시키도록 합니다."* · *"분기는 기존처럼 오른쪽으로 빠지도록 하십시오. 특정 에피소드를
> 끝까지 진행했을 때, 나오는 선택지에서 골라서 가는 것들을 아래로 향하게 합니다. 챕터그래프의 형태를 참고해서."*

| 무엇 | 지금 | 바꾼 뒤 |
|---|---|---|
| 선택지로 가는 다음 에피소드 | 같은 장면 줄의 **오른쪽** | 부모 카드의 **아래**. 자리가 차 있으면 오른쪽으로 비켜 선다 |
| 분기로 다녀갈 카드 | 원본 **아래**(Y + 260) | 원본의 **오른쪽** |
| 레일(선택지 선) | 칩 → 가로 레인 → 도착 카드 **왼쪽** | 칩은 지금처럼 카드 아래에 쌓이고, 레인이 **아래로** 내려가 도착 카드 **위 가운데** 입구로 |
| 분기 · IF 갈래 선 | 카드 오른쪽 → 도착 왼쪽 | 그대로 — 오른쪽으로 빠진다 |
| 챕터 프레임 · 장면 프레임 | 카드만 감싼다 | 카드 아래 레일까지 감싼다 |
| 이미 선 판 | — | 연출 그래프에도 **[자동 정렬]**(판 하나를 위→아래로 다시 세우고 되돌리기 한 칸). 이미 선 카드는 저절로 옮기지 않는다(§5-14) |
| 끌기 | 포인터마다 `MoveNode` | 놓을 때 한 번 적고 되돌리기 한 칸(§6-2) |
| 챕터 그래프 | 자동 정렬 · 새 카드 자리가 왼→오 | 깊이를 **Y축**으로 — 두 판이 같은 방향으로 선다(§6-4) |

선택지 칸은 카드 **아래**에 그대로 둔다(2026-09-16 소유자). 칸을 챕터 그래프처럼 아래변의 점으로 줄이면 한 칸 폭이
카드의 1/4이라 한글 문구가 잘린다 — 문구를 적고 끌어 잇는 연출 그래프의 손놀림을 지키고, 흐름만 아래로 돌린다.

**결과 (2026-10-29)** — 커밋과 CI는 `docs/plans/director-split.md` §3(a `fd4f72f` · b `5d4475b` · c `1e6b819` ·

### D4 — 대사 노드 안에서 쓴다

> *"각각의 대사노드는, 이제 다른 엑셀이나 대본탭에서 작성한 것을 반영하는 게 아니라, 노드 안에 텍스트 공간이 있고
> 그곳에 직접 글을 작성하는 것까지를 목표로 합시다."*

- **카드 안에 여러 줄 글 칸 하나.** 한 줄이 대사 한 줄이고 `화자: 대사`로 쓴다(화자가 없으면 지문). 걷는 대본 탭의 쓰기
  방식(자유 편집 + 넣기)을 카드로 옮기는 것이다.
- **넣는 때는 초점을 잃을 때와 Ctrl+S.** 넣는 길은 `ApplyScenarioText` — diff로 LineId를 지킨다(§5-2). 줄마다 칸을
  두는 안은 줄을 더할 때마다 구조 변경이 판을 다시 그려 초점이 사라지고, 글자마다 되돌리기가 쌓여 버린다.
- 넣기 한 번이 되돌리기 한 칸이 되게 `ApplyScenarioText`의 여러 Mutate를 하나로 묶는다(§5-7).
- 함정(조사에서 확인):
  - 카드 더블클릭이 무대 탭으로 튀고 카드 누르기가 끌기를 시작한다 — 글 칸 안의 누르기는 카드로 올려 보내지 않는다.
  - 휠은 판의 확대가 가로챈다 — 글 칸 위에서는 칸이 스크롤한다.
  - 카드 높이를 어림하는 공식(`CardHeightOf` · `NodeAt`)에 글 칸 높이를 넣어야 레일 · 프레임이 어긋나지 않는다.
  - 곁기둥 대사 편집기와 같은 글을 본다 — 어느 쪽에서 넣든 다른 쪽이 낡은 글로 덮어쓰지 않게 한다.
  - 넣기 전에 다른 노드를 고르거나 저장하면 안 넣은 글을 먼저 넣는다(D2 전의 `FlushPendingEdits` 자리 — 지금은 `FlushWriting`).
  - **새 카드는 빈 줄 하나를 들고 선다.** 그 카드에 `ApplyScenarioText`로 두 줄 이상을 넣으면 "빈 줄을 고친 것인지 지운
    것인지 모른다"로 반영 전체가 거절된다(D2 테스트 변환에서 다섯 에이전트가 모두 걸렸다 — 테스트는 줄 명령으로 피했다).
    카드 글 칸의 첫 넣기는 이 경우를 풀어야 한다: 빈 줄 하나뿐인 대본은 그 줄을 첫 줄로 고친 것으로 본다.

**결과 (2026-10-29)** — 커밋과 CI는 `docs/plans/director-split.md` §3(a `10c922a` · b `9db6863`). 쓰는 모습은 §3.4.

- 위 목록이 전부 섰다. 함정은 테스트로 붙들었다(`CardWritingBoxTests` — 넣기와 초점 · 실패 시 글 남김 · 정돈된 글 ·
  눌렀다 나오기 · 누르기와 더블클릭 · 휠 · 곁기둥 · 다른 카드 누르기 · Ctrl+S, `CardWritingTests` — 빈 첫 줄 · 되돌리기
  한 칸 · 왕복 · 엄격 · 모양만 다른 글).
- 더한 것: **엄격한 넣기**(`strict`). 넣은 뒤 칸은 모델의 모습으로 다시 그려지므로, 반쯤 넣으면 못 넣은 줄이 사람이
  쓴 글에서 조용히 사라진다 — 그래서 문제가 하나라도 있으면 아무것도 안 넣는다. 이를 위해 전환 맞추기를 "계획 →
  적용"으로 나눴다(같은 규칙 한 벌). 줄도 전환도 그대로인 넣기(글이 모양만 다를 때)는 아무것도 적지 않는다(§5-8).
  새 카드 자리의 줄 간격은 글 칸만큼 늘렸다(`NodePlacement.Row` 340 → 400).

  - ~~**붙은 두 줄을 한 번에 고치면 거절된다**~~ — 2026-10-30에 풀었다: 칸이 처음 보인 줄의 신원을 이어 넘긴다(§3.4,
    `ScenarioLineIdentity`). 같은 날 칸은 쓰는 대로 들어가게 됐다(줄 지우기만 칸을 나올 때 — `CardLiveWritingTests`).
  - 카드 글 칸에서 **같은 노드의 곁기둥 칸으로 곧장** 옮기면, 넣기가 곁기둥을 다시 세워 그 첫 누르기가 먹힐 수 있다.

### E2 — 조건 분기를 지운다 (2026-10-29)

> *"에피소드 노드에서 조건 분기를 추가는 가능한데, 현재는 지우는게 불가능 합니다. 지울 수 있도록 해주시고"*

- 「분기 지우기」(`ProjectEditor.RemoveBranchMarker`)는 「분기 추가」의 반대다 — 그 줄 앞의 표식과, 분기가 다녀가던 카드
  (분기를 추가할 때 함께 선 에피소드: 챕터의 행 · 그 간선 · 카드)를 **되돌리기 한 칸**에 걷는다. 대본은 지우지 않는다.
- 그 카드를 **다른 곳이 쓰면 남긴다** — 다른 표식 · 출구가 그리로 가거나, 챕터의 길이 그리로 들어오거나, 시작 노드 ·
  챕터의 시작 에피소드이거나, 다른 판에 서 있을 때. 상태줄이 걷었는지 남겼는지 말한다.
- 창구는 셋이 한 길이다: 대사 편집기의 분기 카드 [✕ 분기 지우기] · 그 줄의 ＋ 메뉴(분기가 있으면 「✕ 분기 지우기」) ·
  연출 그래프에서 분기 선 우클릭. 분기 포트를 빈 곳에 놓는 것은 여전히 **선만 끊는다**(다시 잇는 손짓이다).
- ⛔ 예전 [✕ 분기 제거]는 표식만 걷고 카드를 판에 남겼다(R7 — "써 둔 대사가 한 번의 실수로 사라지면 안 된다").
  그러면 아무도 안 부르는 카드가 판에 서서 사람은 분기가 지워지지 않았다고 본다. 대본은 원래 안 지우고 되돌리기가
  있으므로 그 근거가 없어졌다.

### E3 — 화면에서 LineId를 걷는다 (2026-10-29)

> *"LineId는 필요없으니 화면에 노출되지 않도록 해주십시오."*

- 대사 편집기 줄 표의 LineId 열(머리글 · 칸 · `#`의 툴팁)을 걷었다 — 열은 `# · 화자 · 대사 · ＋`이고, 태그 · 출구 레일은
  화자 열에서 시작한다. 대본에서 사라진 줄의 조건 카드는 LineId 대신 마지막 내용(없으면 "이 대본에 없는 줄")을 보인다.
- 챕터 조건을 지우지 못할 때 쓰는 곳을 짚는 말은 줄을 **차례**로 가리킨다(`1번째 줄의 갈래`).
- 줄 신원(LineId)은 데이터에 그대로 산다 — 글 칸의 넣기가 줄을 지키는 열쇠이고, compositor가 연출을 거는 열쇠다.

### G1 — 왼쪽으로 가는 선택지는 왼쪽으로 (2026-10-29 · H1에서 고쳤다)

> *"선택지 선이 생성 되는 곳이 항상 오른쪽으로만 생성 돼. … 뿌리 에피소드보다 왼쪽에 위치하면 왼쪽으로 생성되도록 해줄래?"*

- 거울에 비춘 줄의 모양 — 칸은 줄기 왼쪽에 서서 점이 줄기 쪽 · 문구가 그 왼쪽이며, 내려가는 레인은 카드 **왼쪽**으로 빠져
  (왼쪽 −12, 가지마다 −8) 도착 카드 위 가운데로 든다. 종료 · 카드 없음 스텁도 왼쪽으로 선다.
- ⛔ 처음에는 「뿌리」를 챕터 시작 에피소드의 카드로 읽고, 그보다 왼쪽에 둔 카드의 선택지를 **카드째** 뒤집었다. 소유자가 뜻한
  것은 그게 아니었다 — 뿌리는 그 선택지가 나가는 카드이고, 뒤집히는 것은 그 선택지 하나다(H1).

### G2 — 왼쪽으로 가는 분기는 카드 왼쪽 포트에서 (2026-10-29 · H1에서 기준을 고쳤다)

> *"분기점 역시 현재는 항상 노드 박스 오른쪽에 생성되는데, 이것도 분기가 뿌리 에피소드보다 왼쪽에 위치하면 박스 왼쪽에 생성되도록 해줘."*

- 카드 안 실행 포트(IF 갈래 · 「분기」)의 쪽은 **도착 카드**로 정한다 — 왼쪽 포트는 카드 **왼쪽** 가장자리에 서고(점이 먼저 ·
  이름이 그 오른쪽), 투영이 `GraphOutputPortProjection.OnLeft`로 싣는다. 아직 안 이은 포트와 다른 판으로 가는 포트는 오른쪽이다.
- 왼쪽 포트의 선은 왼쪽으로 나가 도착 카드의 **오른쪽** 가장자리로 든다(`OrthogonalEdgeRouter.Route(leftward: true)` —
  오른쪽 선을 거울에 비춘 모양, 대상이 가깝거나 오른쪽이면 둘 다의 왼쪽으로 돈다).
- 카드를 끌어 쪽이 바뀌면 자리만 바뀐 변경이어도 그 카드들을 다시 세운다 — 포트 줄이 카드 안이라 자리만 옮겨서는
  쪽이 안 바뀐다.
- ⛔ 처음에는 챕터 시작 카드보다 왼쪽인지로 쟀다(H1에서 출발 카드 기준으로).

### G3 — 선 모양을 손으로 고친다 (2026-10-29)

> *"지금 저런 선이 생기는 모양새가 종종 이상할 때가 있는데, 원한다면 저것도 곡선이나 그런 걸 조절할 수 있도록 해줘. 피그잼처럼"*

- 고칠 수 있는 선은 둘이다 — **선택지 레인**(칩에서 도착 접점까지)과 **실행 선**(분기 · IF 갈래 · 기본 출구). 웹 속으로 드는
  가지 · 종료 · 카드 없음 스텁과 줄기는 그대로다.
- 선을 누르면 선이 파랗게 굵어지고 **손잡이**(흰 점)와 **도구줄** [직각] [곡선] [직선] [↺ 자동]이 선다. 빈 곳을 누르면 내린다.
  레인은 1.4px라 겨누기 어려워 넓고 투명한 같은 선이 누름을 받는다(카드 뒤라 카드를 가리지 않는다).
- **손잡이를 끈다** — 직각이면 꺾이는 자리를 민다(레인: 내려가는 세로 줄은 옆으로 · 도착 위를 건너는 가로 줄은 위아래로,
  실행 선: 가운데 세로 마디를 옆으로만). 곡선이면 굽이의 한가운데를 옮긴다 — 자동 곡선을 t=½에서 둘로 쪼개 가운데 점과
  양옆 제어점을 함께 옮기므로 굽이가 꺾이지 않고 손잡이는 늘 선 위에 있다. 직선에는 손잡이가 없다.
- 끄는 동안은 화면만 굽고, 놓을 때 한 번 적는다(되돌리기 한 칸 — 카드 끌기와 같다). 꼴을 바꾸면 굽이는 처음부터이고,
  같은 꼴을 또 누르면 그대로다. [↺ 자동]은 고친 모양을 걷는다.
- 저장 — 모양은 **손잡이를 자동 자리에서 옮긴 양**(`EdgeShape`: 꼴 · BendX · BendY)이라 카드를 끌어도 굽이가 따라간다.
  레인은 챕터 간선이 진다(`ChapterEdge.Shape` → 매니페스트 `chapters[].edges[].shape`) — 도착 · 문구를 고치거나 에피소드
  이름을 바꿔도 함께 간다. 실행 선은 나가는 노드가 진다(`StoryNode.EdgeShapes` → `.vnstory.json` 노드의 `edgeShapes`,
  열쇠 `detour:{LineId}` · `branch:{LineId}` · `choice:{문구}` · `default`). 출구를 끊으면 그 모양도 걷힌다. 안 고친 선은 아무것도
  남기지 않는다. 흐름과 산출물에는 뜻이 없다(자리만 바뀐 변경 — 판은 선만 다시 긋는다).
- compositor는 이 두 칸을 모르고 지나간다(모르는 칸은 읽지 않는다) — 감독 파일을 읽기만 하는 경계 그대로다.

### H1 — 선 하나하나가 제 도착을 보고 쪽을 고른다 (2026-10-29)

> *"분기는 왼쪽 오른쪽으로 잘 가는데, 선택지는 원래 것보다 왼쪽에 두더라도, 여전히 오른쪽으로 점과 글자가 유지 돼. … 자기
> 루트보다 왼쪽에 있냐 오른쪽에 있냐에 따라서 자신의 선택지 방향이 바뀌는데, 내가 원한 건 그게 아니라 연결되어 있는 루트의
> 현재 연결되어 있는 하나의 루트의 선택지 방향이 바뀌길 원한거야."*

- 규칙 하나(`Graph.EdgeSide.GoesLeft`) — **도착 카드가 출발 카드보다 왼쪽이면 왼쪽으로** 나간다. 카드 왼쪽 X끼리 재고(폭이
  같아 가운데끼리와 같다), 같으면 늘 쓰던 오른쪽이다. 챕터 시작 카드가 어디 있든 상관없고, 낙서판에도 같다.
- 선택지 줄은 **줄마다** 고른다 — 한 카드의 선택지가 왼쪽 카드와 오른쪽 카드로 가면 한 줄은 왼쪽, 한 줄은 오른쪽이다.
  아직 안 이은 칸은 오른쪽이다. 레인은 쪽마다 따로 세어 카드 바깥에 한 줄씩 선다.
- ⛔ 줄기는 줄들이 나가는 쪽의 반대편에 섰다 — 전부 오른쪽이면 카드 왼쪽 안(−30), 전부 왼쪽이면 카드 오른쪽 안, 섞이면
  가운데. 선 하나를 이으면 줄기가 옆으로 뛰어 M에서 **언제나 가운데**로 고쳤다.
- 분기 포트(G2)도 같은 규칙이다 — 출발 카드가 챕터 시작 카드일 때만 예전 규칙과 같았다.
- 판정은 지금 그린 자리로 한다 — 끄는 동안 넘어가는 순간 선택지 줄이 뒤집히고, 분기 포트는 놓을 때 뒤집힌다.

### H2 — 선택지 줄은 사람이 둔 자리에 그대로 (2026-10-29)

> *"현재 선택지 문구를 적어둔 순서가 자꾸 뒤바뀌는데 이거 엄청 헷갈리니 그러지 않게 해. 아마 문구가 있고 선택지가 연결
> 되어있는 걸 가장 위쪽으로 옮기는 로직인가 본데, 그렇게 하지말고 선택지 문구의 순서를 유지해."*

- 원인 — 투영은 이은 칸(간선 순서)을 앞에, 빈 칸을 뒤에 냈고, 적어만 둔 문구는 화면이 「빈 칸들 사이의 차례」로만 들었다.
  그래서 둘째 칸을 먼저 이으면 그 줄이 이은 줄로 위로 올라가 첫째 칸과 자리를 바꿨다. 끊은 문구도 적어 둔 칸들의 맨 앞으로 갔다.
- 이제 화면이 에피소드마다 **줄의 차례**를 든다 — 이은 줄 · 적어 둔 줄(문구) · 빈 칸이 사람이 둔 자리에 선다. 이으면 그 줄이
  제자리에서 이은 줄이 되고, 끊으면 문구를 든 채 제자리에 남는다.
- 간선은 **그 줄 자리에 끼워 넣는다**(`ProjectEditor.AddEdge(before:)` — 그 줄 아래 첫 이은 줄의 간선 앞, 없으면 끝). 그래서
  이은 줄끼리의 차례 = 간선 순서 = 런타임 `OptionIndex`(§5-3)가 늘 화면과 같다.
- 문구 없는 길(진행)은 이은 줄 가운데 맨 아래다 — 예전 소유자 보고("진행이 선택지 위에 서니 헷갈린다") 그대로다.
- 줄 차례는 저장하지 않는다(도착 없는 문구를 담을 칸이 챕터에 없다). 다시 열면 이은 줄이 간선 순서대로 위에 선다 — 이은 줄끼리의
  차례는 간선 순서와 같으므로 잃는 것이 없다. 다른 화면(챕터 그래프)이나 되돌리기로 간선 수가 바뀌면 남는 이은 줄은 끝에서부터
  빈 칸이 되고, 모자라면 마지막 이은 줄 뒤에 선다.

### L — 레거시 정리 (2026-10-29)

- **대사 편집기의 갈래 고르기(W35 · W36)가 없다** — 갈래 시작 줄을 누르면 그 갈래를 고르고 나머지 카드를 흐리던 일이다. 프리뷰 ·
  재생이 먼저 걷혀 이유 없이 줄이 흐려질 뿐이었다. 선택 블록 상자의 머리는 그냥 「선택지」다. 줄을 누르면 [줄 추가]의 자리만 정한다.
- **「{챕터} 설정」 카드가 없다** — 새 판에는 세우지 않고 옛 판의 것은 그리지 않는다(§3.1 표). 조건은 그대로 고른다.
- **챕터 그래프 카드의 ⚠가 켜진다**(§6-12) — 툴에서 만든 에피소드도 오류가 있으면 붉다.
- **검증 보고가 간선을 이름으로 짚는다** — 행 번호 대신 `간선 a → b "문구"` · `'a'→'b' 길`이 문장에 든다. 보고는 심각도 → 자리 →
  낸 순서로 늘어선다.
- **스탯 · 조건을 고치면 그 챕터의 판만 바뀐다**(§6-13).
- 옛 형식(1 · 2) 프로젝트의 거절 안내는 없는 [대본 가져오기] 대신 카드 글 칸을 가리킨다. 옛 저장 키 `excelEpisode` ·
  `sourceRow` · 대본의 `sourcePath`는 읽지 않고 지나간다.

### M — 선택지는 카드 가운데 아래, 카드 머리는 제목만 (2026-10-29)

> *"선택지의 위치가 어떤 때는 노드 중앙이였다가, 어떤 때는 왼쪽으로 치우쳐지는데, 이게 항상 노드 중앙 아래쪽에 선택지가
> 있도록 해줘. 그리고, 노드 종류, 대본 이름, 줄 수가 표시되는데 이 정보는 필요없으니까 치워."*

- **줄기는 언제나 카드 가운데**다. 오른쪽으로 가는 줄은 줄기 오른쪽에(점이 줄기 쪽), 왼쪽으로 가는 줄은 줄기 왼쪽에 선다 —
  줄마다 쪽을 고르는 규칙(H1)은 그대로다. 문구가 길면 레인이 그만큼 바깥으로 비켜 간다.
- **카드 머리는 제목 한 줄**이다. 부제(「대사 · 📄 에피소드 · {대본} · k줄」)와 대사 편집기 머리의 「대본 · k줄 · ko-KR」,
  접힌 판 목록 줄의 「대사」를 걷었다. 에피소드인지는 카드 모양(📄 · 미색 · 각진 모서리)이 말한다.
- 머리 높이를 고정했다(제목 20 + 틈 6) — 포트 줄의 자리를 그 값으로 세므로 글꼴에 맡기면 선 끝이 점에서 비껴 닿는다.
  부제가 있던 머리는 41px인데 46으로 세어 선이 점보다 5px 아래에 닿고 있었다(`GraphCardHeaderTests`).
