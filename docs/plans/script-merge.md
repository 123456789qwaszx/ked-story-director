# 대본을 카드 안으로 — 계획과 단계

> 2026-10-29 소유자: *"1부터 한 뒤에, 2,3까지 진행합니다. compositor도 함께 바꿉니다."* — 앞선 검토(대본 구조가 꼭
> 필요한가)의 ①~③을 모두 한다.

## 1. 왜

대사 카드(`DialogueNode`)는 줄을 직접 들지 않고 `ScriptId`로 따로 선 대본(`ScriptDocument`)을 가리킨다. 저장도 따로다
(`script/*.vnscript.json`). 그렇게 나눈 까닭 — 작가의 대본 파일 가져오기 · 대본을 여러 카드가 나눠 쓰기 · 엑셀 대본 워크북 —
은 모두 걷혔고(D2 · L5), 지금은 **카드와 대본이 늘 1:1**이다. 남은 것은 흔적뿐이다.

- 카드 · 에피소드를 지워도 대본은 안 지워진다 — 프로젝트 목록과 `script/` 폴더에 쌓인다.
- 대본 이름(「new01 대본」)은 카드 이름을 따라가지 않고 화면 어디에도 안 보인다.
- 줄 하나를 찾으려면 늘 `project.FindScript(node.ScriptId)`를 거친다.

**데이터 자체는 필요하다** — 줄 신원(`LineId`) · 줄 개정 번호 · 은퇴한 줄 · locale별 본문 · 반영 개정 번호. compositor가
LineId에 연출을 걸고, 개정 번호를 발행 결과에 싣는다. 걷는 것은 **따로 선 문서**라는 모양이다.

## 2. 결정

| | 무엇 | 결정 | 까닭 |
|---|---|---|---|
| S-D1 | 담는 그릇 | `ScriptDocument`는 **카드가 가진 값**이 된다(`DialogueNode.Script`). Id · 이름 · 프로젝트 목록(`StoryProject.Scripts`) · `ScriptId` · `FindScript`를 걷는다 | 줄 · locale · 개정 번호를 한데 쥐는 그릇은 그대로 쓸모 있다. 걷는 것은 따로 선 신원이다 |
| S-D2 | 편집 명령 | 줄 명령(`InsertScriptLine` · `RetireScriptLine` · `MoveScriptLine` · `SetScriptLineText`)은 **카드 Id**로 부른다. `AddScript` · `EnsureDialogueScript` · `AddDialogueNode(scriptId:)`는 걷는다 | 1:1이면 대본 Id는 카드 Id의 다른 이름일 뿐이다 |
| S-D3 | 남기는 것 | 줄 신원 · 줄 개정 번호 · 은퇴한 줄 · locale(여럿) · `SourceRevision` · `SourceContentHash` | compositor가 읽고(LineId · 개정 번호), 글 반영이 쓴다(은퇴한 줄의 부활 · 바꿀 것 없음 판정). locale 여럿은 번역 자리다 |
| S-D4 | 저장 형식 | 프로젝트 형식 **3 → 4**. 줄은 카드의 판 파일(`story/*.vnstory.json`) 안에 든다(노드의 `script` 칸이 Id 대신 내용). 매니페스트에서 `scripts`가 빠진다 | 파일 하나가 카드 하나를 다 말한다 |
| S-D5 | 옛 형식 3 | **읽어서 옮긴다** — 카드마다 가리키던 대본의 내용을 그대로 넣는다(LineId · 개정 번호 그대로). 여러 카드가 한 대본을 가리켰으면 각자 같은 내용을 갖는다. 가리키는 카드가 없는 대본은 버린다. 형식 1 · 2는 지금처럼 거부한다 | 옮기기가 기계적이다 — 형식 2를 거부한 까닭(어느 문장이 어느 LineId인지 도구가 정해야 했다)이 여기엔 없다 |
| S-D6 | 옛 `script/` 파일 | 옮긴 프로젝트를 **저장할 때** 옛 매니페스트가 가리키던 대본 파일을 지운다(새 파일을 다 쓰고 매니페스트까지 쓴 뒤) | 내용은 판 파일로 옮겨졌다. 남겨 두면 읽지도 않는 사본이 진짜처럼 보인다 |
| S-D7 | compositor | 형식 3 · 4를 **둘 다 읽는다**(쓰지는 않는다 — 그대로). 안의 모델도 director와 같게 카드가 줄을 든다. **compositor를 먼저 내보낸다** — director가 4를 쓰기 전에 읽을 수 있어야 한다 | 경계: compositor는 director 파일을 읽기만 한다 |
| S-D8 | compositor 발행 해시 | 결과 본문의 `sourceScript`(대본 Id)가 빠진다 → 내용이 같아도 **다음 발행 때 새 버전이 한 번** 생긴다. 이미 발행된 결과와 그것을 가리키는 연출은 그대로 유효하다(결과는 불변이다) | 대본 Id가 없어졌으니 실을 것이 없다. 한 번의 새 버전이 옛 Id를 꾸며 내는 것보다 낫다 |

## 3. 단계

한 단계 = 커밋 하나, CI(Windows) 녹색을 보고 다음으로.

| | 무엇 | 상태 |
|---|---|---|
| S1 | **고아 대본 정리** (director) — 카드 · 에피소드 · 판을 지우면 그 대본도 프로젝트에서 빠진다. 열 때 가리키는 카드가 없는 대본은 버린다 | `854f33b` (run 52) |
| S2 | **안에서 합치기** (director) — 카드가 대본을 든다(S-D1 · S-D2). 파일 형식은 그대로라 바이트가 같아야 한다(견본 왕복이 붙든다) | `7083d46` (run 53) |
| S3a | **compositor** — 형식 4 읽기 + 같은 모델 합치기(S-D7 · S-D8) | compositor `9dcd28a` (run 12) |
| S3b | **director 형식 4** — 쓰기 · 형식 3 옮기기 · 옛 대본 파일 지우기(S-D4~S-D6) · 견본 · 문서 | 이번 |
